IP Design
Hierarchical addressing plan for the entire enterprise
✓ Complete

Overview

Before a single cable goes in, the IP addressing plan lays the foundation for everything. AcmeCorp uses 10.0.0.0/8 (RFC 1918 private space) split hierarchically by region and purpose — making routes easy to summarise and the network easy to scale.

Design Decisions

/24s for LANs — 254 usable hosts, easy to remember, clean to summarise at the /20 level per site.

/30s for WAN links — point-to-point links only need 2 hosts. Using a /30 wastes only 2 addresses instead of 252.

10.x.9.x for management — keeping management traffic on a dedicated subnet makes it easy to apply ACLs later and restrict who can reach device management interfaces.

Lessons Learned
💡 Save commands only work from # mode

write memory (or copy running-config startup-config) must be run from privileged EXEC mode (#), not from config mode. Trying it in (config)# throws an invalid input error.

💡 exit vs Ctrl+Z

exit backs you out one level at a time. Ctrl+Z jumps straight back to # from anywhere in config mode — much faster when you need to run a show command quickly.

⚠️ Routing is bidirectional — the big lesson

PC1 could ping HQ-SYD-R1 fine, but pings to ISP-CORE were timing out. The router had the correct outbound route, but the ISP had no return route back to 10.1.1.0/24. Fixed by adding a static route on ISP-CORE:

ip route 10.1.1.0 255.255.255.0 10.1.254.1
💡 Asymmetric routing

When the outbound path works but the return path doesn't — this is called asymmetric routing. Traffic flows out fine but replies never make it back. Always verify both directions when troubleshooting connectivity.
